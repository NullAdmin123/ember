# Ember v2.3.0

## 本次更新

本版本新增永久兑换码与分组观看保号，完善管理员权益编辑、用户筛选和账号展示。观看保号按当前生效分组的规则定期检查累计观看时长，达标保留权益，不达标使对应权益失效；默认关闭，由管理员明确配置后开启。

## 重点功能

- **永久兑换码**：生成、批量生成和编辑兑换码时可选择按天或永久权益，注册与已有用户兑换使用同一套分组发放规则。兑换历史保留发放时的有效期类型，之后修改兑换码不追溯修改已发放权益；Web 与 Telegram 均能正确显示永久兑换结果。
- **分组观看保号**：分组配置保号开关、考核周期天数和最低观看分钟数，默认周期 30 天。仅考核当前生效组；被其他组替代期间暂停考核，实际接替时重新获得完整周期。达标不延长限时权益的自然到期日，也不解除人工限制。
- **失效与恢复**：观看不足使对应权益失效，有其他有效组时回退，否则关闭资源访问。关闭保号、普通换组或后续补看不会自动恢复失效权益；重新购买对应组或管理员明确授予/恢复后重新起算。
- **观看要求展示**：概览展示当前生效组的观看要求；账号中心逐条展示开启保号的持有权益要求及首次检查日期。Bot 识别保号失效状态，不再将失效永久权益显示为可用。
- **有效持有权益筛选**：用户列表新增“持有权益组”，与“当前分组”组合时取交集；仅匹配仍有效的永久或未到期权益，排除保号失效记录，避免多权益导致重复用户和分页计数错误。

## 问题修复

- 修复保号判定提交后中断导致 Emby 权限同步遗漏：失效状态与待同步任务在同一事务保存，提交后即时处理，中断后由既有 worker 恢复；旧任务完成不能覆盖新任务。
- 保存每用户扫描进度，下一轮优先处理尚未尝试及最久未尝试的用户，避免任务超时、取消或统计失败后尾部用户持续遗漏。统计失败或响应不完整时保留权益，不按零观看处理。
- 统一配置保存、运行期注册与首次考核日期的日历 cron 校验，拒绝 `@every` 和表达式自带时区；已有无效配置仅暂停保号，并保留权益读取能力。
- 修复分组表单将空观看门槛自动补为 `1` 的问题；开启保号必须明确填写，关闭时空值继续按 `0` 保存，已有正数在开关切换时保留。
- 修复设置中心保存失败后的未处理异常，保留草稿并恢复保存按钮，允许修改后重试。
- 管理员资料修改与延期在同一事务完成，重试不会重复增加天数；无偏移日期按全局业务时区解析。

## 体验优化

- 统一管理员权益编辑与延期入口，直接提供延期、指定到期时间和设为永久；编辑用户默认保持当前期限不变，换组与改期限分开操作。
- 明确区分“权益有效期”与“兑换截止时间”，避免将兑换码无截止时间误认为兑换后获得永久权益。
- 普通用户账号中心不再展示容易误认成登录账号的 Emby ID 卡片；管理员保留“Emby 关联”，明确标注用户 ID 和关联状态。
- 补齐保号调度注册、下一次执行时间、每轮分类汇总及权限同步终态日志。“考核完成”仅在事务提交成功后记录；回滚、旧任务和未领取任务不误报成功，详见[观看保号运行手册](../runbooks/watch-retention.md#线上日志观察)。

## 升级说明

- **本版本包含 3 份数据库迁移**：`20261005_01_redemption_permanent_validity.sql` 增加兑换码与历史有效期类型；`20261008_01_watch_retention.sql` 增加保号配置、权益状态与审计；`20261011_01_watch_retention_scan_progress.sql` 增加扫描进度表。SQL 随 API 镜像分发，由启动期 Migrate 自动执行，支持窗口内无需手工逐份执行。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点，无 baseline 压缩或迁移归档。
- 从 `v2.2.0` 升级时，现有兑换码保留按天语义、原天数及使用次数，不重发已兑换权益；保号默认关闭，不在升级时使存量权益失效。从更早版本跨越升级还须遵循 [v2.2.0 升级说明](./v2.2.0.md#升级说明)，包括旧兑换码失效、分组等级配置等权益改版要求。
- 升级前备份数据库，API、Gateway、Web 和 Bot 使用同一发布版本；API 与 Gateway 共用 `EMBER_API_IMAGE`。确认启动日志中 `[Migrate]` 完成且 schema 校验通过后再验收功能。已执行这些 SQL 的预览环境由迁移记账跳过，不需要重复手工运行或清空记录。
- 默认镜像更新为 `v2.3.0`；使用 `.env` 或 Compose override 固定镜像的部署须同步调整覆盖值。无新增必填环境变量，既有密钥与 Bot 更新模式保持不变。
- 新增设置中心配置 `WATCH_RETENTION_SCHEDULE`，默认 `0 2 * * *`，受 `CRON_ENABLED` 控制，使用唯一业务时区 `CRON_TIMEZONE`；调度配置修改后重启 API 生效。分组开启保号需明确填写正整数分钟门槛，启用状态下修改周期或分钟数会重开当前有效用户的考核周期；仅切换分组保号配置不要求重启 API。
- 观看统计合同针对 **Emby Server 4.9.3.0 + Playback Reporting 2.1.0.7**。启用前确认 Emby 时区与 `CRON_TIMEZONE` 一致，插件持续记录且历史保留期覆盖考核周期。统计按播放开始时间选取窗口内电影/剧集记录并累计播放减暂停时长，多设备相加；不逐秒裁剪跨窗口播放或合并设备重叠。已被插件删除的历史无法靠一次成功查询识别。
- 外部兑换码调用方可使用 `validityType=duration/permanent`；永久权益须明确使用 `permanent` 且 `defaultDays=0`，省略类型仍按原按天规则处理，不从零天推断永久。兑换响应与历史记录增加有效期类型。

## 已知限制与验证边界

- 发布准备基于 `f18c84e`，补正一处历史 Emby Token 集成测试夹具的资源授权状态，未修改生产权限判断。修正后 Go 全量 47 个包、3012 项测试及子测试通过，零跳过，包含专用 PostgreSQL 隔离 schema 集成回归；临时 schema 自动清理，vet 与 build 通过。Web 清洁安装后 348 项测试通过、3 项既有集成测试跳过，类型检查与生产构建通过；Bot 使用项目 Python 3.11 虚拟环境完成依赖安装、语法检查及 83 项测试。
- 官方独立 Compose `v5.6.0` 已核对官方 SHA256，并使用占位配置通过 `config --quiet` 和镜像版本检查，覆盖 Gateway、Bot profiles；未启动 Docker 或项目服务。
- 基线 [GitHub CI](https://github.com/konghanghang/ember/actions/runs/38115927077) 成功，API/Web 作业通过、Bot 作业按路径规则跳过；同提交的 [API](https://github.com/konghanghang/ember/actions/runs/38116352536)、[Web](https://github.com/konghanghang/ember/actions/runs/38116352526)、[Bot](https://github.com/konghanghang/ember/actions/runs/38116352527) 预览镜像均构建成功。这些记录不代表尚未执行的正式 tag 构建。
- 依赖审计尚未清零：清洁安装报告 23 项告警（6 moderate、17 high），生产依赖审计报告 3 high，涉及 `@vue/server-renderer`、其上层 `vue` 及 `source-map-js`。构建模块检查确认两个受影响组件均未进入浏览器 bundle，Vue 使用 runtime 构建，生产镜像只部署静态文件与 Nginx，不包含 Node 依赖目录；当前部署的可利用路径未证实，告警保留，本轮未自动升级依赖。
- **Telegram 群签到及“观看或签到任一达标即可保号”尚未实现**，当前仅有后续计划；本版本的保号依据仍是观看时长。
- 同代码基线 `f18c84e` 的预览部署已确认四个服务健康、两份新增保号迁移执行成功及调度注册；受检环境的保号分组全部关闭，尚未验证真实用户考核、真实播放统计与失效后的 Emby 权限同步。用户端观看要求的完整浏览器验收仍未完成，自动化与 mock 不能替代这些实机证据。
- Bot polling 更新期间曾发生单实例租约冲突并自动恢复；部署时避免同一 Bot 并行运行多个 polling 实例，出现 `409` 时先核对租约持有者和续租情况，不直接删除有效锁。
- 保号每轮仍有 10 分钟预算，持久化进度保障后续扫描推进，不保证超出处理能力的全部用户都能在当天完成考核。
- 正式发布仍需推送版本 tag，并确认 API、Web、Bot 正式镜像及 Draft Release 工作流成功；公开 Release 和生产部署由维护者手工完成。
